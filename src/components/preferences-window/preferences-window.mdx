<Example name="basic" both />

The window an application opens with Command-comma. It is a [Window](/components/window) with
a unified [Title Bar](/components/title-bar) that holds a
[Preferences Toolbar](/components/preferences-toolbar), and a body that shows the pane of the
selected item. The title follows the selection, and the frame resizes to each pane.

## Usage

```tsx
import { Checkbox } from "macalicious/checkbox";
import { PreferencesToolbar, PreferencesToolbarItem } from "macalicious/preferences-toolbar";
import {
  PreferencesWindow,
  PreferencesWindowForm,
  PreferencesWindowPane,
  PreferencesWindowRow,
} from "macalicious/preferences-window";
import "macalicious/styles.css";

<PreferencesWindow
  width={480}
  onClose={close}
  toolbar={
    <PreferencesToolbar aria-label="Preferences">
      <PreferencesToolbarItem value="general" icon={<GeneralIcon />}>General</PreferencesToolbarItem>
      <PreferencesToolbarItem value="advanced" icon={<AdvancedIcon />}>Advanced</PreferencesToolbarItem>
    </PreferencesToolbar>
  }
>
  <PreferencesWindowPane value="general">
    <PreferencesWindowForm>
      <PreferencesWindowRow label="Show:">
        <Checkbox defaultChecked>Birthdays calendar</Checkbox>
      </PreferencesWindowRow>
    </PreferencesWindowForm>
  </PreferencesWindowPane>
  <PreferencesWindowPane value="advanced">…</PreferencesWindowPane>
</PreferencesWindow>
```

- The first toolbar item that has a value and is not disabled is selected unless
  `defaultValue` or `value` says otherwise (`defaultValue={null}` starts with no pane). Pass
  `value` and `onValueChange` to control the pane, for example to restore the pane last viewed.
- The title is the label of the selected item, read from the `PreferencesToolbarItem` elements
  given to the toolbar, directly or in fragments. Pass `title` (and `defaultValue`) when the
  items are wrapped in components of your own.
- `PreferencesWindowForm` and `PreferencesWindowRow` lay out the usual pane: a column of
  right-aligned labels and a column of controls, centred as a block. A child of the form that
  is not a row, such as a [Separator](/components/separator) or a checkbox, spans both columns.
- `PreferencesWindowFooter` is the bottom row: a [Help Button](/components/help-button) alone,
  or Cancel and OK in the modal kind.
- The window does not move, order or close itself: a window manager gives it `state` and a
  position through `style`, moves it from `onDragRegionPointerDown` (a press on the title bar,
  not on a window control or a toolbar item), and unmounts it on `onClose`.

## Guidelines

From the Human Interface Guidelines for macOS,
[Preferences](https://web.archive.org/web/20200503145009/https://developer.apple.com/design/human-interface-guidelines/macos/app-architecture/preferences/):

- Reserve preferences for settings people change rarely. A setting changed with every task
  belongs in the window it affects or in a panel.
- A preferences window is a modeless dialog. Apply each change at once; there is no OK or
  Cancel.
- Disable the minimize and zoom buttons: the window is for occasional adjustments and is not
  resized.
- Set the title to the name of the visible pane; with a single pane, to "App Name Preferences".
- Restore the pane last viewed when the window is opened again.

Music and TV in Catalina depart from this, as iTunes did: their preferences are a modal dialog
without window controls, with Cancel and OK. `modal` reproduces that kind.

## Variants and states

<Example name="modal" both />

| Prop | Values | Source |
| --- | --- | --- |
| `modal` | `false` (default): modeless, close button enabled, minimize and zoom disabled. `true`: a dialog without window controls that takes the focus when it appears and is closed by Escape. `controls` given explicitly are shown in it all the same | Measured: modeless in Calendar, Mail, Safari and Podcasts; modal in Music and TV |
| `state` | `key` (default), `main`, `inactive` | As [Window](/components/window); an inactive preferences window is provisional, no screenshot shows one |
| `animated` | `true` (default): the frame animates between pane sizes over 0.2 s | Provisional: the screenshots are stills; the duration is an estimate of AppKit's |

Row alignment (`align` on `PreferencesWindowRow`): `baseline` (default) lines the label up with
the first line of text in its control; `center` and `start` are for controls without text.

## Sizes

A preferences window is not resizable. Give it the `width` of its widest pane (Calendar 537,
Mail 550, Safari 774 points) or leave the width out and it fits its content; its height is the
selected pane's unless `height` is set. Margins and spacing, all measured on Calendar, Mail and
Safari: 20 pt around a pane, 8 pt from a label to its control, rows 10 pt apart (a 30 pt pitch
with 20 pt controls), 20 pt above and below a separator between sections.

## Accessibility

- The window is a `region` named by its title, so the name announces the visible pane. The
  modal kind is a `dialog`. It takes the keyboard focus when it appears and gives it back to
  the element that had it when it is removed, unless the focus has moved elsewhere meanwhile.
  A control with `autoFocus`, in a pane or in a portal, keeps the focus it asked for.
  It does not contain focus or make the rest of the page inert by itself, so it does not set
  `aria-modal`: present it in the library's dialog or sheet, which do both, when the page
  behind it must be unavailable.
- The toolbar is a `tablist` and each pane the `tabpanel` of its item; see
  [Preferences Toolbar](/components/preferences-toolbar) for the keys. A pane is a tab stop
  and shows the focus ring inside its edge while it holds the keyboard focus, in a key window.
- A row's label is a `<label>` for the control named by `labelFor`. Without `labelFor` the
  row's controls form a `group` named by the label, which suits a label followed by checkboxes.
- Escape calls `onClose` in the modal kind only, and not while a menu or pop-up button is
  open in a pane: that Escape closes the menu. An open pop-up is recognised by its button
  (`aria-expanded` with `aria-haspopup`), by its list being in a portal, or, for a list in
  the pane itself, by the open button naming it in `aria-controls`. A modeless window is
  closed with its close button (and Command-W, which is the application's to handle).
- The frame's size animation is skipped for a visitor who prefers reduced motion.

## Visual comparison

`preferences-window.visual.json` compares the whole frame of Music's preferences (the modal
kind: centred toolbar, a form of labels and checkboxes, two separators, and a footer with
help, Cancel and OK) with the reference screenshots in both appearances. The toolbar icons
(Apple artwork) and the List Size pop-up button are left out of the example and masked. Music
lays its form out against the left edge with row heights of its own, so the example sets the
label column's width and the rows' heights. The centred default layout is measured on Calendar,
Mail and Safari (see Sizes); it is compared where those windows are built: the
[Calendar demo](/demos/calendar) compares its whole General preferences window, a
`PreferencesWindow` of the modeless kind with its pop-up buttons, with the Calendar Preferences
captures in both appearances (`preferences-light` and `preferences-dark` in
`demos/calendar/calendar.visual.json`, each with a masked layout twin).
