<Example name="basic" both />

AppKit's `NSToolbar`. It is built on [Base UI's Toolbar](https://base-ui.com/react/components/toolbar),
which makes it one tab stop with arrow keys between its items. The toolbar has no background of
its own: it shares the surface of the [Title Bar](/components/title-bar) it is a child of.

## Usage

```tsx
import { TitleBar } from "macalicious/title-bar";
import { Toolbar, ToolbarSpace } from "macalicious/toolbar";
import { ToolbarButton } from "macalicious/toolbar-button";
import { ToolbarSearchField } from "macalicious/toolbar-search-field";
import "macalicious/toolbar.css";

<TitleBar variant="unified" title="Network">
  <Toolbar aria-label="Finder">
    <ToolbarButton aria-label="Share">{/* glyph */}</ToolbarButton>
    <ToolbarSpace />
    <ToolbarSearchField style={{ width: 240 }} />
  </Toolbar>
</TitleBar>
```

Items are [Toolbar Button](/components/toolbar-button),
[Toolbar Segmented Control](/components/toolbar-segmented-control) and
[Toolbar Search Field](/components/toolbar-search-field), each optionally wrapped in a
[Toolbar Labelled Item](/components/toolbar-labelled-item). They register with the toolbar's
keyboard navigation by themselves. `ToolbarSpace` is flexible space; with `width` it is a fixed
gap.

## Guidelines

Not verified: this section paraphrases Apple's Human Interface Guidelines and was not checked
against Apple's text.

- A toolbar gives quick access to frequent commands. Every item must also exist as a menu
  command.
- Use the toolbar controls only in a toolbar, and ordinary controls only in the window body.
- Clicking an item acts at once. Only a segmented control or a toggle toolbar button keeps a
  selected look.
- Put the search field last, at the trailing edge, after flexible space.
- Prefer a glyph to text in an item, and give every glyph-only item a name.

## Variants and states

<Example name="display-modes" both />

| Display mode | What shows | Chrome height in a unified bar |
| --- | --- | --- |
| `icon-only` (default) | The controls | 55 pt (measured: Finder) |
| `icon-and-label` | Every labelled item shows its label under its control | 68 pt (measured: Console; Disk Utility is 70 pt, see the padding hook) |
| `label-only` | Labelled items show only their label | provisional: no screenshot shows it |

In a `title-hidden` title bar the controls sit on the 38 pt row beside the window controls. The
toolbar itself looks the same in a key, main and inactive window; its surface and its items
change (see their pages).

## Sizes

A toolbar has no `size` prop. Its width is the title bar's; its height comes from its items
and the display mode (the table above). Items keep their own 22 pt height; the gap between
them is 8 pt and can be changed with `--mac-toolbar-gap`.

## API

<PropsTable name="ToolbarProps" />

<PropsTable name="ToolbarSpaceProps" />

| Attribute or variable | Values | Description |
| --- | --- | --- |
| `data-display-mode` | `icon-only`, `icon-and-label`, `label-only` | Reflects `displayMode`; read by labelled items. |
| `data-flexible` | present or absent, on `.mac-toolbar-space` | A space without `width`. |
| `--mac-toolbar-gap` | a length | Space between items. Default 8px (measured); Safari has 10 pt after its Back and Forward pair. |
| `--mac-toolbar-padding-top` | a length | Space above the controls. Default 3px under a title strip and 8px in a title-hidden bar; Disk Utility has 4px. |

## Accessibility

- `role="toolbar"` from Base UI. Give it an `aria-label`.
- One tab stop: Tab enters and leaves, and the Left and Right arrow keys move between items,
  wrapping at the ends. Base UI's Toolbar does not handle Home and End. In a search field the
  arrow keys move the caret until it reaches an end of the text.
- A text field in the toolbar selects its text when the keyboard moves focus to it, and takes
  the caret where it is clicked, as in AppKit. Base UI's toolbar selects the text on every
  focus; the toolbar leaves that out for a focus caused by a mouse press on the field.
- `ToolbarSpace` is hidden from assistive technology.
- The toolbar does not collapse items into an overflow menu when the window is too narrow, as
  AppKit does; items keep their size and the bar clips. Lay out for the narrowest width.
