The AppKit control is `NSTextField` with a bezel. `TextField` is built on Base UI's
[Input](https://base-ui.com/react/components/input), so it works inside a Base UI `Field` and
reports changes through `onValueChange`. The bezel and the focus ring are drawn by a wrapper
element, because an `<input>` cannot draw them itself.

## Usage

```tsx
import { TextField } from "macalicious/text-field";
import "macalicious/text-field.css";

<TextField aria-label="Computer name" defaultValue="Catalina" />
<TextField placeholder="Optional" value={name} onValueChange={setName} style={{ width: 240 }} />
```

Or copy the source into your project: `npx macalicious add text-field`.

`value`, `defaultValue`, `onValueChange`, `disabled`, `readOnly`, `placeholder`, `name`, `id`
and every other input attribute go to the `<input>`. `className`, `style` and `ref` go to the
root element; `inputRef` reaches the `<input>`. The field is 160 pt wide unless `style` sets
its width.

## Guidelines

From the macOS Human Interface Guidelines for text fields:

- Give the field an introductory label in title case that ends with a colon, or placeholder
  text in sentence case without punctuation.
- Validate when people leave the field or press Return, not on every keystroke.
- Use a secure text field for sensitive data, and a number formatter for numbers.
- Decide what happens to text that does not fit: clip it, wrap it or truncate it, and offer an
  expansion tooltip for clipped text (see [Tooltip](/components/tooltip)).
- Keep fields of one form the same width where you can.

| State | How it is triggered | Look | Status |
| --- | --- | --- | --- |
| Enabled | – | White fill (white at 5% in Dark Aqua), hairline edge, inner line | measured (Sharing) |

| `bezel` | Look | Status |
| --- | --- | --- |
| `square` | Square corners, 20 pt high | measured |

The capsule is the field Messages and FaceTime type into. Put a button inside its trailing
end as a child of the field, as Messages does with its emoji button; the text takes the rest
of the width.

```tsx
<TextField bezel="capsule" aria-label="Message" placeholder="iMessage">
  <ImageButton aria-label="Emoji" style={{ marginInlineEnd: 3 }}>
    {emoji}
  </ImageButton>
</TextField>
```

A field takes the font it is given: its text is not tied to the three control sizes. Contacts
edits a card's name in place at about 18 pt (capitals 13 pt high in

### Bezel only

`TextFieldBezel` is the bezel without the `<input>`: the edge, the fill and the focus ring
around content of your own. Use it for a control that looks like a text field but edits
something else, such as the segments of a date, so that it does not copy the bezel's values.
`TextField` is this bezel around a Base UI Input.

```tsx
import { TextFieldBezel } from "macalicious/text-field";

<TextFieldBezel role="group" aria-label="Date" style={{ width: "auto" }}>
  {segments}
</TextFieldBezel>
```

<Example name="bezel-only" both />

- It is a `<div>`: every `<div>` prop, `className`, `style` and `ref` go to it. It lays its
  children out in a row, centred on the line, and gives them no padding; the text field's own
  text starts 3.5 pt inside the edge.
- The focus ring shows while anything inside has the keyboard, in the key window only. With
  `focusRing={false}` the bezel never draws it, for content that draws its own.
- `--mac-text-field-background`, set on the bezel or an ancestor, replaces the fill. It applies
  to `TextField` as well.
- `disabled` only draws the disabled edge and text colour. Disable the controls inside.
- The role, the accessible name and the keyboard behaviour are those of the content.

## Accessibility

- The control is a native `<input>`: it is always in the tab order, Return submits its form,
  and the standard editing keys work.
- Name it with a visible label (`<Label render={<label htmlFor={id} />}>`), a Base UI
  `Field.Label`, or `aria-label`. A placeholder is a hint, not a name.
- `disabled` uses the real attribute, so the field leaves the tab order. Use `readOnly` when
  the text should stay selectable.
- The focus ring shows whenever the field has the keyboard, for pointer focus too, as in
  AppKit, and only in the key window.
- In forced-colours mode the edge uses `ButtonText`, a disabled field `GrayText` and the ring
  `Highlight`.

placeholder masked.

The masked comparison uses a threshold of 0.05 and gates the bezel. States no screenshot shows
on a plain text field are checked pixel by pixel against the spec's values, with real input:
every hairline of the bezel at rest, the focus ring after a click (ring over the window, over
the edge and over the inner line), the missing ring in a window that is not key, and the
disabled edges. `TextFieldBezel` is checked the same way: the ring when its content has the
keyboard, no ring with `focusRing={false}`, and the overridden fill.
