<Example name="basic" both />

AppKit's `NSSegmentedControl` in the textured rounded style. With a toggle
[toolbar button](/components/toolbar-button) it is one of the two toolbar controls that may
show a lasting selection. It is built on
[Base UI's Toggle Group](https://base-ui.com/react/components/toggle-group) and keeps its API,
so the value is an array, also when one segment is selected.

## Usage

```tsx
import { ToolbarSegment, ToolbarSegmentedControl } from "macalicious/toolbar-segmented-control";
import "macalicious/toolbar-segmented-control.css";

<ToolbarSegmentedControl aria-label="View" defaultValue={["columns"]} onValueChange={setView}>
  <ToolbarSegment value="icons" aria-label="Icons">{/* glyph */}</ToolbarSegment>
  <ToolbarSegment value="list" aria-label="List">{/* glyph */}</ToolbarSegment>
  <ToolbarSegment value="columns" aria-label="Columns">{/* glyph */}</ToolbarSegment>
</ToolbarSegmentedControl>
```

A momentary control keeps no selection; give each segment an `onClick`:

```tsx
import { ToolbarSegment, ToolbarSegmentedControl } from "macalicious/toolbar-segmented-control";

<ToolbarSegmentedControl variant="navigation" tracking="momentary" aria-label="Navigation">
  <ToolbarSegment aria-label="Back" onClick={back}>{/* glyph */}</ToolbarSegment>
  <ToolbarSegment aria-label="Forward" onClick={forward} disabled>{/* glyph */}</ToolbarSegment>
</ToolbarSegmentedControl>
```

## Guidelines

Not verified: this section paraphrases Apple's Human Interface Guidelines and was not checked
against Apple's text.

- Use a segmented control for closely related choices or commands: view modes, zoom out and
  in, back and forward.
- Segments hold either glyphs or text, never a mix within one control, and should be equal in
  width.
- The control is one toolbar item: 8 pt to its neighbours.

## Variants and states

<Example name="variants" both />

| Variant | Look | Seen in |
| --- | --- | --- |
| `joined` (default) | One bezel divided by 1 pt dividers | Finder's view switcher |
| `separated` | A bezel per segment; the bezels touch | Preview's zoom buttons |
| `navigation` | A bezel per segment, touching | Back and Forward |

| Tracking | Behaviour |
| --- | --- |
| `select-one` (default) | A selected segment stays selected: clicking it again does not deselect it, so one segment is always selected once one is. Start it with a `defaultValue` or `value` that names a segment |
| `select-any` | Each segment toggles on its own |
| `momentary` | Segments are plain buttons |

| State | How it is triggered | Look |
| --- | --- | --- |
| Selected segment | its value is in `value` | The on bezel of a toolbar button; the dividers on both its sides disappear |
| Pressed | `:active` | provisional |
| Disabled | `disabled` on the control or a segment | Dimmed glyph |
| Keyboard focus | `:focus-visible` | Focus ring on the segment, in the key window only (provisional) |
| Main window | `data-window-state="main"` on an ancestor | As in the key window, selection included (measured: Finder behind Quick Look), without the focus ring |
| Inactive window | `data-window-state="inactive"` on an ancestor | Flat outlined bezel, grey glyphs. A selected segment of a joined control is a flat grey fill inside the outline (`#e3e3e3` on the bar's `#f6f6f6`; Dark Aqua `#535557` on `#2b2d2f`) with its title as dim as the others (measured: the Books toolbar). In the separated and navigation styles it is the key window's fill at half strength (provisional) |

## Sizes

One size: the control is 22 pt high, as every toolbar control in the screenshots. A segment is
as wide as its content plus padding, and at least 25 pt (27 pt for the first and 29 pt for the
last of a joined control, whose outer ends carry the rounded corners). Set `style={{ width }}`
on a segment for an exact width.

## API

<PropsTable name="ToolbarSegmentProps" />

| Attribute | On | Values | Description |
| --- | --- | --- | --- |
| `data-variant` | control | `joined`, `separated`, `navigation` | Reflects `variant`. |
| `data-tracking` | control | `select-one`, `select-any`, `momentary` | Reflects `tracking`. |
| `data-pressed` | segment | present or absent | Set by Base UI on a selected segment. |
| `data-disabled` | control, segment | present or absent | Set by Base UI. |
| `data-force` | segment | `pressed`, `focus` | Documentation and visual tests only. |

## Accessibility

- The control is a group: give it an `aria-label`. Every segment that shows only a glyph needs
  one too.
- Selecting segments are toggle buttons with `aria-pressed`, as Base UI's Toggle Group renders
  them; momentary segments are plain buttons. AppKit exposes a select-one control as a radio
  group; the toggle-button form is the one a toolbar's arrow-key navigation can include.
- On its own the control is one tab stop with arrow keys between segments. In a
  [Toolbar](/components/toolbar) its segments take part in the toolbar's navigation.
- Space and Return select or activate the focused segment.
