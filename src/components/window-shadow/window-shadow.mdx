On a Mac the shadow is not part of the window: the window server draws it, sized by the
window's level and by whether it is key. Here it is a rounded box with one `box-shadow`, taken
from the elevation tokens, which were fitted to the alpha falloff of the transparent window
captures. [Window](/components/window) is built on it; use it directly for a floating surface of
your own.

## Usage

```tsx
import { WindowShadow } from "macalicious/window-shadow";
import "macalicious/window-shadow.css";

<WindowShadow level="panel" style={{ width: 240, height: 120 }}>
  A floating surface
</WindowShadow>
```

The component draws the shadow, the outer hairline and the corner radius, and nothing else:
give the surface its own background and clip.

## Guidelines

Not verified: this section paraphrases Apple's Human Interface Guidelines and was not checked
against Apple's text.

- The shadow signals layering. The key window casts the largest one, an inactive window a
  smaller one, and transient surfaces (menus, popovers, utility panels) a small tight one.
- The shadow takes no part in layout. Leave 48 pt at the sides, 31 pt above and 67 pt below a
  key window if its shadow must not be clipped by a scrolling or `overflow: hidden` ancestor.
- The change of shadow between key and inactive is a second cue beside the window controls'
  colour; do not rely on it alone.

## Variants and states

<Example name="levels" both />

| Level | Used by | Token |
| --- | --- | --- |
| `window` | Document and application windows, dialogs | `--mac-shadow-window`, or `--mac-shadow-window-inactive` in an inactive window |
| `panel` | Utility panels | `--mac-shadow-panel` |
| `menu` | Menus | `--mac-shadow-menu` |
| `popover` | Popovers | `--mac-shadow-popover` |
| `banner` | Notification banners | `--mac-shadow-notification` |
| `none` | A full-screen window | no shadow; the radius stays |

Only the `window` level changes with the window state: it follows `data-window-state="inactive"`
on the element itself or on an ancestor. The other levels belong to surfaces that are key while
they are open.

## Sizes

No sizes: the shadow surrounds whatever box the element has and takes no part in layout. The
`level` prop chooses how large the shadow is.

## API

<PropsTable name="WindowShadowProps" />

| Attribute or variable | Values | Description |
| --- | --- | --- |
| `data-level` | `window`, `panel`, `menu`, `popover`, `banner`, `none` | Reflects `level`. |
| `--mac-window-shadow-radius` | a length | Corner radius of the surface. Default: `--mac-radius-window`, 5 pt. |

## Accessibility

The shadow adds no role, text or focus stop. In forced-colours mode shadows are not drawn, so
the surface gets a system-colour outline instead and its edge survives.

What is and is not exact:

- The key, panel and banner shadows are fitted to captures with a root-mean-square error of
  0.002 to 0.004 in alpha. The inactive shadow is recovered by differencing a window over the
  desktop against the bare desktop.
- A CSS shadow is one Gaussian per layer; the window server's falloff is close to, but not
  exactly, that. The difference is under one 8-bit level.
- The hairline is half a point: at 1x it becomes a whole pixel at the same alpha.
- No screenshot shows the menu, popover or banner levels changing with window state; they do
  not change here.
