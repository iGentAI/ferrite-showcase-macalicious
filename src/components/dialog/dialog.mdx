A dialog is an `NSWindow` or `NSPanel` that an application runs to ask for one or several
values: Finder's Go to Folder and Connect to Server, the Cancel and OK of a preferences dialog.
The parts are built on Base UI's [Dialog](https://base-ui.com/react/components/dialog) and keep
its anatomy; `DialogPopup` combines Base UI's portal and popup with the library's
[Window](/components/window) and [Title Bar](/components/title-bar), because a dialog window is
always assembled the same way. A dialog that belongs to one window is a
[Sheet](/components/sheet); one that warns is an [Alert](/components/alert).

## Usage

```tsx
import { DefaultButton } from "macalicious/default-button";
import { Dialog, DialogActions, DialogClose, DialogPopup, DialogTrigger } from "macalicious/dialog";
import { Label } from "macalicious/label";
import { PushButton } from "macalicious/push-button";
import { TextField } from "macalicious/text-field";
import "macalicious/styles.css";

<Dialog>
  <DialogTrigger render={<PushButton />}>Go to Folder…</DialogTrigger>
  <DialogPopup title="Go to Folder" width={429}>
    <Label id="folder-label">Go to the folder:</Label>
    <TextField aria-labelledby="folder-label" defaultValue="~/Documents/" />
    <DialogActions>
      <DialogClose>Cancel</DialogClose>
      <DialogClose render={<DefaultButton />} onClick={go}>Go</DialogClose>
    </DialogActions>
  </DialogPopup>
</Dialog>
```

Or copy the source into your project: `npx macalicious add dialog`.

- Open it with `DialogTrigger`, or control it with `open` and `onOpenChange` on `Dialog`.
- `title` is the window title and names the dialog. `controls` takes a
  [Window Controls](/components/window-controls) element for a dialog that has them.
- The body has the standard 20 pt margins and is yours to lay out. `DialogDescription` is a
  paragraph that assistive technology reads as the dialog's description.
- `DialogActions` is the button row: its children are the dismissing buttons, at the trailing
  end with the action last; `leading` takes a [Help Button](/components/help-button) or
  buttons that change the content. `DialogClose` is a [Push Button](/components/push-button)
  that closes the dialog; `render={<DefaultButton />}` makes it the
  [Default Button](/components/default-button).
- The dialog appears centred, 20% of the viewport's height from its top. Move it down or up
  with `--mac-dialog-top` or with `top` in `style`, which the component turns into that
  variable, so the height limit follows either. `left` and `margin` in `style` place it
  sideways. It does not move by itself: a window manager can, with
  `onDragRegionPointerDown` and `onDragRegionDoubleClick` on `DialogPopup`, which report a
  press and a double click on the title bar itself, not on a window control in it.
- A modeless dialog stays open while another window has the keyboard. A window manager says
  so with `state` on `DialogPopup` (`"key"`, `"main"` or `"inactive"`), and the frame, the
  window controls and the default button are drawn for that state.

## Guidelines

From the Human Interface Guidelines for macOS,
[Dialogs](https://web.archive.org/web/20200503145009/https://developer.apple.com/design/human-interface-guidelines/macos/windows-and-views/dialogs/):

- Fill in default values wherever possible, so that people can accept the dialog at once.
- Put the initial focus on the first control that accepts typing.
- Mark the button people are most likely to want as the default button, and never a
  destructive one.
- Place the buttons that dismiss the dialog at the bottom right, the action rightmost and
  Cancel to its left. Buttons that change the dialog's content go at the left.
- Prefer a sheet when the request concerns one window, and a modeless panel when people need
  to keep working while it is open.

## Sizes

A dialog takes the width of its content, or `width` (Go to Folder is 429 pt, Connect to Server
486 pt); its height follows its content. Measured on Finder's dialogs: 20 pt margins on all
sides (20.5 pt to a control's visible edge), 20 pt between the last control and the buttons,
buttons 12 pt apart (13 pt between their bezels) and at least 84 pt wide. Preferences-style
dialogs use 70 pt buttons: set `--mac-dialog-button-min-width`.

## Accessibility

- The dialog is a `dialog` named by its title; without a `title`, give it an `aria-label`.
  A modal dialog makes the rest of the page inert and hides it from assistive technology; a
  modeless one (`modal={false}`) does neither.
- When it opens, the focus goes to the element marked `data-autofocus`, else to the first text
  field, else to the window itself; `initialFocus` overrides that. Checkboxes, buttons and
  whatever cannot take the focus (disabled, inert, hidden or not focusable) are passed over.
  When it closes the focus returns to the control that opened it. A dialog opened without a
  `DialogTrigger`, from a menu item that is gone by then or from your own state, has no such
  control: name where the focus goes with `finalFocus` on `DialogPopup`.
- Return activates the default button from anywhere in the dialog, also from a text field.
  Escape closes the dialog, which is what Cancel means. A click outside does not.
- Window controls in the title bar are buttons with names of their own; the dialog's own
  buttons remain the way to answer it.

appearances: Finder's Go to Folder dialog (app-modal, no window controls) and its Connect to

and every comparison masks it. Connect to Server holds a combo box, a list of favourite
servers and a segmented add, remove and action control, which are other components too: the
