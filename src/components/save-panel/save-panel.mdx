<Example name="basic" both />

AppKit's `NSSavePanel`. The collapsed form is a name field, a Tags field and a Where pop-up
button of recent and favourite places; the disclosure button beside the name expands it to the
file browser of the [Open Panel](/components/open-panel). The default button is "Save".

**No screenshot of the reference set shows a Save panel.** The layout on this page is
inferred: from the Human Interface Guidelines, from the Print sheet (the form of right-aligned
labels) and from the Open panel (the browser). It is made only of measured parts of the
library: a [Text Field](/components/text-field), a [Token Field](/components/token-field), a
[Pop-up Button](/components/pop-up-button) (Base UI's Select), a
[Disclosure Button](/components/disclosure-button), a [Push Button](/components/push-button)
and a [Default Button](/components/default-button).

## Usage

```tsx
import { SavePanel, SavePanelRow } from "macalicious/save-panel";
import { Sheet, SheetPopup } from "macalicious/sheet";
import "macalicious/styles.css";

<Sheet open={open} onOpenChange={setOpen}>
  <SheetPopup anchor={titleBar} width={440} aria-label="Save">
    <SavePanel
      defaultName="Letter.rtf"
      locations={[{ value: "documents", label: "Documents" }]}
      defaultLocation="documents"
      onSave={({ name, tags, location }) => save(name, tags, location)}
      onCancel={() => setOpen(false)}
    />
  </SheetPopup>
</Sheet>
```

- **It is the panel's content**, a form with no frame, fill or margin of its own. Put it in a
  [Sheet](/components/sheet) on the document's window, which is how AppKit presents it, or in
  the body of a [Window](/components/window) with the usual 20 pt margin.
- **The values** are the name, the tags and the place. Each is controlled (`name`, `tags`,
  `location`) or kept by the panel (`defaultName`, `defaultTags`, `defaultLocation`), and
  `onSave` receives all three. Saving is yours: a page cannot write the file system.
- **Save is disabled** while the name is empty, and with `saveDisabled`.
- **The name without its extension is selected** the first time the field takes the focus,
  so that typing replaces it.
- **More rows** go in `accessory` as `SavePanelRow` elements, which line up with the panel's
  own: a File Format pop-up button, as in the example above.
- **Other languages.** `nameLabel`, `prompt` and `cancelLabel` are props; the remaining texts
  ("Tags:", "Where:", "New Folder" and the disclosure button's names) are in `labels`.

### Expanded

<Example name="expanded" both />

Give `browser` the props of `OpenPanelBrowser` (a `sidebar`, the file view as `children`,
`canGoBack` and the others; not the place, which stays the panel's `location`), and the panel
gets its disclosure button. Expanded, the Where row
gives way to the browser's location button, which shows the same place; the accessory rows
move under the browser; and `onNewFolder` adds a New Folder button at the leading end of the
button row. `expanded`, `defaultExpanded` and `onExpandedChange` control the form. The browser
reaches the edges of the surface around the panel: set `--mac-save-panel-bleed` to that
surface's margin if it is not 20 pt.

## Guidelines

From the Human Interface Guidelines for macOS,
[Dialogs](https://web.archive.org/web/20200503145009/https://developer.apple.com/design/human-interface-guidelines/macos/windows-and-views/dialogs/)
(not verified against the archived page; paraphrased from the measured spec):

- Use the system's Save dialog, attached to the document's window as a sheet, so that it is
  clear which document is being saved.
- Open it on the place the user last saved to, and remember whether it was expanded.
- Offer the formats the document can be saved in from the dialog itself, in an accessory.
- The default button saves; Cancel leaves everything as it was.

## Variants and states

| State | Look | Source |
| --- | --- | --- |
| Collapsed | Name, Tags and Where in one column; Cancel and Save | Provisional: no screenshot |
| Expanded (`browser`) | Name and Tags, the Open panel's browser, accessory, then New Folder, Cancel and Save | Provisional: the browser is measured on the Open panel, the arrangement is inferred |
| Without tags (`showsTagField={false}`) | No Tags row | Provisional |
| Name empty, or `saveDisabled` | Default button disabled | Provisional |
| Not key | No accent on the default button and the pop-up button | Provisional |

The sheet's height does not animate when the panel expands.

## Sizes

One size. The fields and the Where button are 252 pt wide (`--mac-save-panel-field-width`),
8 pt apart, with right-aligned labels 8 pt before them; the disclosure button stands 8 pt
after the name field. The button row is 20 pt under the last row, its buttons 12 pt apart and
at least 70 pt wide (`--mac-save-panel-button-min-width`). The browser is 320 pt high
(`--mac-save-panel-browser-height`). A collapsed panel suits a sheet about 440 pt wide.

## Accessibility

- The panel is a `form` named "Save" (or by `aria-label`, `aria-labelledby`). The dialog is
  the sheet or window around it: name that too, and let it move focus in. A sheet focuses the
  first text field, which is the name.
- "Save As:" and "Tags:" are `<label>`s of their fields; the Where button is named by its
  label. A `SavePanelRow` labels its control with `labelFor`, or lends its label's `labelId`
  to a control that takes no `<label>`.
- Return activates the default button and Escape (and Command-Period) activates Cancel from
  anywhere in the panel, unless the focused control uses the key itself: an open menu, the
  Tags field while it holds text to turn into a tag. Neither answers in a window that is not
  key.
- The disclosure button is named "Show the file browser" or "Hide the file browser", has
  `aria-expanded`, and points at the browser with `aria-controls`.
- In the expanded form the browser's toolbar is one tab stop, as in the Open panel.

## Visual comparison

No screenshot shows a Save panel, in either appearance. `save-panel.visual.json` therefore
compares the one part that has a reference: the toolbar of the expanded form's browser, against
the toolbar of TextEdit's Open panel at the same width (914 pt), since the two panels share
the browser. The first row and the corners of that capture belong to the Open panel's window
frame and are masked; the masked comparisons hide the glyphs and text as well.

Scores from `npm run visual -- save-panel` in Chromium on Linux with the fallback font: the
share of pixels that differ by more than the threshold, and the mean colour difference out of
255.

| `browser-toolbar-light-drawing` (masked) | same | 5.44% | 3.07 | 0.66% | 1.34 |

The collapsed form is checked without a reference: `collapsed-light` and `collapsed-dark` read
ten pixels of a 440 pt wide panel, which place the three controls in one column 8 pt apart and
the two buttons at the trailing end, in the colours of the controls they are.

Everything about the form's arrangement is provisional: the widths, the gaps, the place of
the disclosure button, the height of the browser and the order of the expanded form. Not
built: the animated change of height, the "Hide extension" checkbox (give it as an accessory),
the Go to Folder sheet, and replacing an existing file.
