AppKit calls this control a *bevel button* (`NSButton` with the regular-square bezel style and
the on/off button type). Catalina shows it in one place, the Orientation buttons of the Print
dialog. It is built on [Base UI's Toggle](https://base-ui.com/react/components/toggle), and
`BevelButtonGroup` on [Toggle Group](https://base-ui.com/react/components/toggle-group).

## Usage

```tsx
import { BevelButton, BevelButtonGroup } from "macalicious/bevel-button";
import "macalicious/bevel-button.css";

<BevelButton pressed={snap} onPressedChange={setSnap}>Snap</BevelButton>

<BevelButtonGroup aria-label="Orientation" value={value} onValueChange={setValue}>
  <BevelButton value="portrait" aria-label="Portrait"><PortraitIcon /></BevelButton>
  <BevelButton value="landscape" aria-label="Landscape"><LandscapeIcon /></BevelButton>
</BevelButtonGroup>
```

A button on its own holds its state in `pressed` (or `defaultPressed`). In a group each button
has a `value`, and the group's `value` is the list of the ones that are on; `multiple` allows
more than one. Or copy the source into your project: `npx macalicious add bevel-button`. See
[Installation](/installation).

## Guidelines

From the macOS Human Interface Guidelines for bevel buttons:

- A bevel button can have square or rounded corners and show text, an icon or another image.
- The guidelines advise against it in modern applications: use a push button, a checkbox, a
  pop-up button, radio buttons or a segmented control instead.

## Variants and states

Pressed and keyboard-focused are transient, so this gallery pins them. In an application they
appear on their own.

<Example name="states" both hideCode />

| State | How it is triggered | Look |
| --- | --- | --- |
| Off | – | Gradient that is lighter at the bottom, 1 pt border, no shadow |
| On | `pressed`, or the group's `value` | The same gradient, darker, in Aqua; a flat lighter grey with no visible border in Dark Aqua |
| Pressed | `:active` | As on |
| Keyboard focus | `:focus-visible` | Focus ring over the border |
| Disabled | `disabled` | The content at 25%; the bezel does not change |
| Rounded | `variant="rounded"` | Rounded corners |
| Window not key | an ancestor has `data-window-state="main"` or `"inactive"` | Unchanged, but no focus ring |

## Sizes

One size. A button is at least 38 x 38 pt, the size of the Print dialog's buttons, and grows
with its content; set `width` and `height` for another size. A group puts 12 pt between its
buttons.

## Accessibility

- Each button is a native `<button>` with `aria-pressed`. Space and Return toggle it.
- A button that holds only an image needs an `aria-label`.
- The group has `role="group"` and is one stop in the tab order; the arrow keys move between
  its buttons. Name it with `aria-label` or `aria-labelledby`.
- AppKit exposes the Print dialog's pair as radio buttons. The group here reports toggle
  buttons, which announce "pressed" rather than "selected"; for a true radio group use radio
  buttons.
- In forced-colours mode the border is drawn with system colours and a button that is on has
  an inner outline.

## Visual comparison

The example `visual-orientation` reproduces the Orientation pair of the Print sheet (portrait
on, landscape off) and is compared with the screenshots in both appearances by
`npm run visual` (`bevel-button.visual.json`). The two pictograms are masked: the example
draws stand-ins, not Apple's artwork, so only the bezels are scored. Share of pixels that
differ at 2x at half the default colour distance, in Chromium on Linux:

| Crop, 98 x 48 pt, pictograms masked | Aqua | Dark Aqua |
| --- | --- | --- |
| Portrait (on) and landscape (off) | 0.00% | 0.00% |

The size, the border and both gradients are measured. In Dark Aqua the Print sheet is a
vibrant material: its colour varies by a few levels from pixel to pixel in the screenshot, and
the example paints it flat. That stays below the colour distance that counts as a difference
and shows only in the mean colour difference, 1.3 of 255 against 0.8 in Aqua.

No screenshot shows a bevel button pressed, focused, disabled or with rounded corners; those
looks are the spec's inference and provisional. They are checked in a real browser against
the spec's values (the `expect` comparisons): borders and fills at rest, the on fill under a
real mouse press and after a real click, the focus ring after a real Tab, the dimmed content
of a disabled button, and that the ring is absent in an inactive window. For the rounded
variant the example `visual-rounded` checks that the corner of the box is cut and that the
fill and border are those of the square button; its radius is the control radius, an inference
with no measurement behind it.
