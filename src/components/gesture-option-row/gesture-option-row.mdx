<Example name="basic" both />

The Mouse and Trackpad panes list their gestures beside a preview. Each gesture is a checkbox
with two lines of text: its name, and under it a description or a choice of how the gesture is
made. One row at a time has a callout behind it whose point aims at the preview: it marks the
gesture the preview is showing, which is not the same thing as the gesture being on. AppKit
has no public class for the row. `GestureOptionRow` composes the library's
[checkbox](/components/checkbox) (Base UI's Checkbox) with the two lines and draws the callout
in CSS.

## Usage

```tsx
import { GestureOptionRow } from "macalicious/gesture-option-row";
import "macalicious/checkbox.css";
import "macalicious/gesture-option-row.css";

const [shown, setShown] = useState("scroll");

<GestureOptionRow
  title="Scroll direction: Natural"
  detail="Content tracks finger movement"
  defaultChecked
  highlighted={shown === "scroll"}
  onPointerEnter={() => setShown("scroll")}
  onFocus={() => setShown("scroll")}
/>
```

Or copy the source into your project: `npx macalicious add gesture-option-row`.

Stack the rows without a gap: each is 50 pt tall, the pitch of the panes. Give the list the
width the callout should span (311 pt in the Mouse pane) and leave about 35 pt between it and
the preview. The row does not decide which gesture is highlighted; its owner does, usually
from the pointer entering a row or focus reaching it:

<Example name="preview" both />

`detail` takes text or a control. In the Trackpad pane the second line of some gestures is a
borderless pull-down button that chooses the fingers; pass that control as `detail` and it
stays a separate stop in the Tab order.

## Guidelines

From the macOS Human Interface Guidelines on
[checkboxes](https://web.archive.org/web/20200503145009/https://developer.apple.com/design/human-interface-guidelines/macos/buttons/checkboxes/)
and
[preferences](https://web.archive.org/web/20200503145009/https://developer.apple.com/design/human-interface-guidelines/macos/app-architecture/preferences/):

- Gestures are independent settings, so each is a checkbox. Do not make the list a radio
  group, and do not turn a gesture on because its row became highlighted.
- Name the gesture in the title and say how it is made in the second line.
- A preference applies as soon as it changes; there is no Apply button.
- Disable a choice that depends on a gesture while that gesture is off.

## Sizes

One size. The row is 50 pt tall and as wide as its container. The checkbox is the regular
14 pt box, 10 pt from the leading edge; the text starts 35 pt from it. The title is 13 pt
regular and the second line 11 pt regular, 16 pt from baseline to baseline. The callout is as
wide as the row and 53 pt tall, so it reaches 1.5 pt beyond the row above and below; its last
24 pt are the point. Text that does not fit before the point is cut with an ellipsis.

## API

<PropsTable name="GestureOptionRowProps" />

The remaining props are those of a `<div>` and go to the row, not to the checkbox.

| Attribute or variable | On | Values | Description |
| --- | --- | --- | --- |
| `data-highlighted` | row | present or absent | Reflects `highlighted`; draws the callout. |
| `data-disabled` | row | present or absent | Reflects `disabled`. |
| `--mac-gesture-option-row-callout-fill` | any ancestor | a colour | Fill of the callout. |
| `--mac-gesture-option-row-callout-edge` | any ancestor | a colour | Half-point edge of the callout. |
| `--mac-gesture-option-row-callout-highlight` | any ancestor | a colour | The line under the callout's top edge. |

Classes: `.mac-gesture-option-row`, `.mac-gesture-option-row-checkbox` (the checkbox, which
also has `.mac-checkbox` and its own attributes), `.mac-gesture-option-row-text`,
`.mac-gesture-option-row-title` and `.mac-gesture-option-row-detail`.

## Accessibility

- Each row exposes one `checkbox`, named by the title and described by the second line. Tab
  reaches it and Space toggles it; clicking the title toggles it too and leaves focus on the
  checkbox, as clicking the checkbox does.
- The highlight is not a selection and sets no ARIA state: `aria-checked` belongs to the
  checkbox alone. When the highlight changes what a preview shows, describe the preview in
  text or give it a live region, as the example above does.
- Move the highlight on focus as well as on pointer entry, so that keyboard users see the same
  preview.
- A control passed as `detail` is a separate stop after the checkbox and keeps its own name.
  It also becomes the checkbox's description, so keep its label short.
- In forced-colours mode the callout is an outline one point wide in the system's text colour.
