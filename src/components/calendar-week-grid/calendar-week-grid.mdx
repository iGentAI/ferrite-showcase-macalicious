<Example name="basic" both />

The week (or day) view of the Calendar application: a title with the month and year, the day
names with today's number in a red disc, a row for all-day events, and a scrolling grid of the
24 hours in which each event is a block as tall as it is long. AppKit has no such view, it is
Calendar's own, and Base UI has no primitive for it, so the component is written here. It draws
what it is given: it runs no clock, loads no calendars and creates no events.

## Usage

```tsx
import { CalendarWeekGrid, type CalendarWeekGridEvent } from "macalicious/calendar-week-grid";
import "macalicious/styles.css";

const events: CalendarWeekGridEvent[] = [
  {
    id: "screenshots",
    title: "Make Catalina Screenshots",
    start: new Date(2019, 9, 3, 14),
    end: new Date(2019, 9, 3, 16, 45),
    color: "light-dark(#c157d9, #cc74e1)",
  },
];

<CalendarWeekGrid
  start={new Date(2019, 8, 29)}
  now={new Date(2019, 9, 3, 15, 38)}
  events={events}
  style={{ height: 480 }}
/>
```

Or copy the source into your project: `npx macalicious add calendar-week-grid`.

- Give the grid a height (`style`, `className`): the header keeps its size and the hours scroll
  in what is left. `defaultScrollHour` is the hour at the top edge at first.
- `start` is the first day and `days` their number: 7 for a week, 1 for Calendar's day view.
  The title names the month and year of the middle day.
- Dates are read in local time. An event that crosses midnight is drawn in each day it
  touches; one that ends at midnight stays in its day. Events outside the days shown are left
  out, so the whole list can be passed.
- `color` is the colour of the event's calendar, any CSS colour; `light-dark()` gives one per
  appearance. Events without one take `--mac-calendar-week-grid-event-color`, Calendar's blue
  by default.
- `now` marks today and draws the current-time line. Pass a new date, from a timer of your
  own, to move it; without `now` neither is drawn.
- `accessory` sits at the trailing end of the title row. Calendar puts its previous, Today and
  next control there: a [Segmented Control](/components/segmented-control).

<Example name="controlled" />

A click selects an event and a click beside the events, in the hours or in the all-day row,
clears the selection (`value`,
`defaultValue`, `onValueChange`). A double click, or Return on a focused event, calls
`onEventAction` with the event and its element; Calendar shows the event's
[Popover](/components/popover) then, anchored to that element.

## Guidelines

The Human Interface Guidelines for macOS describe no calendar view; these notes describe what
Calendar on macOS 10.15 does, as the reference screenshots show it.

- Colour belongs to the calendar, not to the event: every event of a calendar has the same
  colour, and the selected event is the one drawn solid.
- Show the current time only in a period that contains today.
- Keep event titles short. A block shows the start time and as much of the title as fits.

## Sizes

The component has no control sizes. The header is 80 pt (a 51 pt title row and 29 pt of day
names), the all-day row 26 pt with its line and band and 20 pt more for each further row of
events, the gutter 74 pt, and an hour is `hourHeight` points: 40 by default, 39 1/3 in the
reference capture, where Calendar shows twelve hours in the window. Lines and events are put on
half points, as AppKit puts them on the device pixels of a 2x display.

## API

`CalendarWeekGrid` takes the props of a `<div>`, which go to its root with `ref`, `className`
and `style`, and these:

<PropsTable name="CalendarWeekGridProps" />

An event is a `CalendarWeekGridEvent`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the event in `value`. |
| `title` | `string` | The event's name. |
| `start`, `end` | `Date` | Its time span, in local time. |
| `allDay` | `boolean` | Draws it in the all-day row, across the days from `start` to `end`. |
| `color` | `string` | The colour of its calendar. |

| Attribute | On | Values | Description |
| --- | --- | --- | --- |
| `data-weekend` | day name, column, all-day cell | present or absent | Saturday and Sunday. |
| `aria-current="date"` | day name | present or absent | The day of `now`. |
| `aria-pressed` | event | `true`, `false` | The selected event. |
| `data-event-id` | event | the event's `id` | Finds an event's element, to anchor a popover to it. |

| CSS variable | Default | Description |
| --- | --- | --- |
| `--mac-calendar-week-grid-columns` | `repeat(<days>, minmax(0, 1fr))` | The grid tracks of the day columns. At the reference window's width AppKit rounds the seven columns to 123, 124, 124, 124, 123, 123 and 121 pt. |
| `--mac-calendar-week-grid-event-color` | Calendar's blue, `#1dadf8` | The colour of events that have none. |

Classes: `.mac-calendar-week-grid` (the root), `-header`, `-title`, `-days`, `-day`,
`-day-number`, `-all-day`, `-scroll`, `-body`, `-column`, `-hour`, `-now`, `-now-dot`, `-event`
and `-event-time`, each prefixed with `.mac-calendar-week-grid`.

## Accessibility

- The title is a heading, and it names the scrolling grid, which is a `group` and a tab stop so
  that the hours can be scrolled from the keyboard.
- Every event is a `<button>` in the tab order, in the order of the days. Its name is its
  title, its day and its times (“Make Catalina Screenshots, Thursday, October 3, 2019, 2 PM –
  4:45 PM”), and `aria-pressed` says whether it is selected. Space and Return select it; Return
  also calls `onEventAction`, as a double click does.
- Today's name carries `aria-current="date"`.
- The colour of an event is never its only information; give calendars names where they are
  listed, as Calendar's sidebar does.
- The names of the days and the dates in the events' names follow `locale`. The times follow
  `formatTime`, and `noonLabel` and `allDayLabel` are yours to translate.
- In forced colours every event has a border, and the selected one a thicker border.
- Arrow keys do not move between events; that is left to Tab. Dragging to move, resize or
  create events is not built.
